# 转写错误记录（PLAN 9/7）

目标：用 3 段真实对话找出 SenseVoice-small int8 在台湾业务场景下会错在哪，
决定 10 月要不要换模型、要不要做词汇表后校正。

## 怎么用
1. 用 App 正常录一段真实对话（不要念稿）。
2. 转写完成后，逐段点回放对照原话。
3. 只记**错的**段落，对的不用记。
4. 一段录音一个区块，填完更新最后的统计。

## 分类
| 代号 | 类别 | 说明 |
|---|---|---|
| `NAME` | 人名 | 人名、公司名、职称。含同音错字 |
| `NUM` | 数字 | 金额、日期、数量、电话、型号 |
| `MIX` | 中英夹杂 | 中文句子里的英文词、缩写（KPI、demo、follow up） |
| `NOISE` | 噪音 | 环境音、多人同时讲、距离远造成的漏字或乱码 |
| `OTHER` | 其他 | 不属于上面四类 |

## 严重度
按「会不会让 LLM 产生错的 FACT」分，不按听起来多怪。

| 代号 | 意思 | 例子 |
|---|---|---|
| `FATAL` | 改变事实 | 金额、日期、人名被换成别的 |
| `NOISY` | 读得懂但要猜 | 同音错字、语助词乱入 |
| `MINOR` | 不影响理解 | 标点、语气词 |

## 已经知道的问题

- **同一段音频重复辨识结果不稳定**：9/4 用同一句话重复 108 次测试，
  SenseVoice 输出 開飯／派飯／菜飯／派放 等不同结果。
  同样的音在不同位置会被辨识成不同的字，不是随机噪音造成的。
- 目前没有词汇表后校正，人名与公司名只能靠模型本身。
